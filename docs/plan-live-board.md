# 计划：现场看板、呼叫店员、计时提醒、网页结账、预约上限（2026-10-05 业主定）

店里有柜台电脑、手机和平板。现场操作原本只在小程序（见 `plan-staff-web-admin.md` 的划分），这一批让柜台电脑常开一个**现场看板**，
和店员手机实时联动；顾客在座位上能**呼叫店员**；计时**快到点、超时**两端都提醒；柜台电脑上也能**结账、打印小票**；
顾客自助预约**每人最多 2 个**，再多找门店。

## 1. 预约上限与门店联系方式

- 顾客自助预约（`book`）每个账号同时最多 **2** 个还没到店的预约（待确认、已确认都算）。超出回 409 `reservation_limit_reached`，
  小程序提示「每个账号最多同时预约 2 个座位，更多座位请联系门店」并显示联系方式。
- **店员代客登记（`register`）不受这个上限**：顾客电话、微信约第 3 个，由店员登记。同一顾客同一时段不能重复的规则照旧。
- 预约设置加两个可选字段：门店电话 `contactPhone`、门店微信号 `contactWechat`，老板在网页后台「预约设置」里填。
  小程序在超限提示、包间说明、预约须知里显示：电话点一下拨号，微信号点一下复制。没填时只写「请联系门店」。

## 2. 呼叫店员

- 谁能叫：有**进行中计时会话**（计时中或暂停中）的顾客，在小程序「本次手作」页点「呼叫店员」。散客没有账号会话的不支持。
- 一个会话同时只有一条未处理的呼叫；处理后 **1 分钟**内不能再叫；未处理的呼叫 **30 分钟**后显示为已过期（读时算，同入座申请的做法）。
- 店员：实时推送。小程序工作台顶部显示「X 桌 呼叫 · N 分钟前」和「已处理」，新呼叫到达时手机振动；网页看板侧栏列出、可处理。
  处理记入审计（谁、何时）。顾客页看到「店员马上就到」。
- 网页提醒是全站的（2026-10-06 业主反馈：看板放在后台或停在别的页面时收不到，刷新才看到）：挂在登录后的布局上，
  不论在哪一页、标签页在不在前台都提醒，看板的呼叫栏只列出与处理、不另外提醒。呼叫事件到达时后台标签页也立刻重读未处理的呼叫
  （只这一条查询破例，其余仍是后台只标过期），另每 30 秒兜底重读。新呼叫：右上角提示（不在看板页时留到处理或关掉）；
  提示音默认开，打开页面后第一次点击或按键自动开启（浏览器的自动播放限制），之前顶部提示「点一下页面任意处开启提示音」；
  系统通知用浏览器的 Notification（不做 Web Push / Service Worker，Chrome 推送依赖谷歌服务），在「提醒设置」里点按钮授权，
  页面不在眼前时弹出、点它回看板；后台时标签页标题闪「(N) 新呼叫」。「提醒设置」在账户菜单和呼叫栏头部，按浏览器存在 localStorage。
- 新表与迁移、接口进契约：顾客建呼叫、店员查未处理的、店员标记已处理。

## 3. 计时提醒

- 用后端已有的 `remainingSeconds` / `endsAt`（桌位接口已经算好），不在前端自己算业务状态，只在两次刷新之间按 `endsAt` 倒数显示。
- **快到点**：剩余 10 分钟以内；**已超时**：剩余小于 0。自由计时没有结束时间，不提醒。
- 小程序工作台加「快到点 / 已超时」列表（按剩余时间排序）；网页看板上对应座位变色并排在提醒栏。

## 4. 网页现场看板

- 网页后台新增「现场」页，适合柜台电脑或平板全屏常开：
  - 平面图（同小程序那张底图和点击区域，取自 `layout/store-layout.json`，不另存一份）：每个座位显示空闲／使用中（剩余时间）／暂停／快到点／已超时／停用，
    以及 30 分钟内要到店的预约。
  - 侧栏：呼叫店员、待确认的扫码入座（确认／拒绝）、即将到店的预约（到店开台）、快到点与超时。
  - 点使用中的座位：会话详情和常用操作（暂停、继续、续时、停止计时并去结账），沿用现有接口与权限。
    下面是不常用的换桌（按座会话换座）、标记陪客、撤销误开（2026-10-06 业主定：网页也要能办，小程序保留），
    行为、前置条件、权限和确认同小程序员工端：整桌会话 `PATCH /venue-sessions/{id}`（换桌带目标桌，陪客 `status: companion`）、
    `DELETE /venue-sessions/{id}`（撤销，先确认、危险样式写清后果）；按座会话 `/loyalty/actions` 的 `move`（带 sessionVersion、目标桌和座号），
    没有陪客和撤销。目标从看板已读到的桌位与当班占用里选，有人、停用的灰着写明原因；被拒时显示后端原话。
  - 点空闲、启用的座位：「开台」侧栏（2026-10-06 业主问「网页为什么不可以开台」后补上，柜台有电脑）。整桌开台，
    调现有 `POST /venue-sessions`，内容同小程序开台页：顾客（服务端搜索，不选为散客）、已发布计时套餐的时长（标价）、其他时长、
    到打烊或自由计时、开始时间默认「现在」（没改就取点确认那一刻），可回填——店员 60 分钟内、店长和老板当天，前端只做提示与限制。
    这张桌今天还有预约时先提醒；后端拒绝（座位被预约、桌已被占、无权回填）显示原话、保留输入。契约里这个接口不收幂等键，
    结果未知再点一次时，上次开成了的话后端回「桌位正在使用」，不会重开。点停用的座位只提示不能开台。
- 实时更新沿用现有事件流；呼叫的提示音、系统通知等提醒是全站的，见第 2 节。

## 5. 网页结账与小票

- 网页后台新增结账页（待结账订单）：明细（计时套餐自动行与商品）、人工折扣（店长、老板）、会员结账（余额、积分抵扣）、收款登记，
  规则与小程序结账页一致，金额只以接口返回为准。手机结账保留。
- 付款后可打印小票（浏览器打印，适配 58mm／80mm 小票纸与普通 A4）：门店名、订单号、时间、明细、折扣、实收、付款方式、会员余额与积分变化。
- 入口：看板上「停止计时并去结账」、订单页的待结账订单。

实现：结账页 `/checkout/$orderId`，小票 `/receipt/$orderId?paper=58|80|a4`（这台电脑记住上次选的纸宽）；订单列表与详情里待结账的有「去结账」，
收过款的有「打印小票」。之后补齐了三处（两端结账页一起）：草稿订单可事后绑定、更换顾客或改散客（`PATCH /sales-orders/{id}/customer`）；
现金可填实收、后端记找零（迁移 017，付款记录的 `cashReceivedCents`、`changeCents`）；小票印「本单结账后余额」（订单 `memberCheckout.balanceAfter`，由会员流水推出）。规则见 `product.md`「结账」。
