# 计划：员工复杂功能搬到电脑网页后台

> 2026-10-04 制定。业主决定：**顾客端不动，仍是小程序**；员工端在小程序里只留现场常用的，
> 复杂的、要坐下来处理的搬到电脑网页后台。小程序、网页、后端三端实时同步。本文只定方案，**不含代码改动**。
>
> **进度**：第 0 批已确认；第 1 批 2026-10-04 上线（0.0.2）；第 1b～4 批 2026-10-05 上线（后端 0.0.3、0.0.4）；第 5 批（小程序员工端瘦身）随小程序 0.0.4 上传体验版。待真机验收；小程序正式版 2026-10-20 已发布（0.0.26）。

## 0. 为什么、搬什么

小程序在员工这一侧的限制是实打实踩过的：改一次要构建→预览→上传、正式版还要审核；主包 2MB 上限、
上传会剔掉「没被静态引用」的图片；Linux 开发者工具靠社区版、自动化测试难，单测全绿真机却坏过多次；
导出的 Excel 和数据文件只能「分享/打开」不能直接下载；不能直连打印机；电脑版微信里一个窗口、不能多标签。
顾客那一侧这些都不痛，扫码直达和微信一键登录反而离不开小程序。

划分原则：**站着、随手、每天做的留在小程序；坐下来、成批、偶尔做的去网页。**

## 1. 架构

- **后端不分家**：还是同一个 Go 模块化单体、同一套 `/api/v2`、同一套权限校验、幂等键和订单版本，网页只是另一个客户端。
- **网页前端**：新目录 `pindou-admin/`，纯前端单页应用，由 Go 后端直接提供。技术栈（2026-10-04 业主确认）：
  - React 19 + Vite + TypeScript，包管理用 pnpm（小程序仍是 npm，各管各的锁文件）。
  - 组件库 **Semi Design**：用主包 `@douyinfe/semi-ui`，React 19 在入口最先引入 `@douyinfe/semi-ui/react19-adapter`（官方已不再推荐单独的 `@douyinfe/semi-ui-19`），图标 `@douyinfe/semi-icons`。
    用 Semi **默认主题**，不覆盖颜色变量、不做品牌配色（DESIGN.md 的品牌色只管小程序），品牌只体现在标志和文案上；
    自写样式只管布局。表格用 **Semi Table**。
  - TanStack：**Query**（缓存；实时事件到达后让对应资源过期重读；**不做乐观更新**，金额库存只以后端为准）、
    **Router**（类型安全路由；筛选、分页、排序、标签页放网址参数；路由加载数据时配合 Query）、
    **Form**（表单状态与校验，配 Zod，输入控件用 Semi 的，不再用 Semi Form）、**Pacer**（搜索防抖；
    一串实时事件合并成一次重读）、**Devtools**（仅开发时）。订单、审计、库存流水这类长列表由服务端分页，不用 Virtual。
    不用 Start（全栈渲染框架，多一个 Node 服务）、DB（0.5 测试版，前端本地数据库加乐观写入，违反「前端不保存业务状态」）、
    Table（与 Semi Table 重复）、Store（Query 加网址参数已够）。
  - 校验 Zod；测试 Vitest + Testing Library，端到端 Playwright；ESLint + Prettier；时间一律按门店时区（东八区）格式化。
  - API 客户端手写一份，语义照搬 `services/staff.ts`（幂等键、`expectedVersion`、409 后重读再确认），不为两端预建共享包。
- **托管**：前端构建产物用 `go:embed` 打进 `pindou-api` 镜像，由同一个进程在后台域名下提供，
  前后端版本天然一致、发布还是一个镜像、同源调用不用配 CORS。域名 `pindou-admin.personal.example.invalid`（2026-10-19 起是 `admin.example.invalid`），
  DNS 指向腾讯云、Traefik 自动签证书。网页页面要另配 CSP（API 现在是 `default-src 'none'`）。
- **登录：微信扫一扫**（0.0.8 起）。网页拿 pollToken 换一张指向小程序「电脑登录」页的小程序码，员工用微信扫一扫直接打开；生成不了时退回普通二维码，在小程序「扫码登录电脑」（`wx.scanCode`）扫 →
  确认后网页拿到一张**网页会话**。复用 `web_login_challenges` 的思路，按现在的规则重做（挑战码一次性、几分钟过期、
  未登录接口限流、批准要求员工角色、全程审计）；网页会话与小程序会话分开、有效期更短、可在小程序里一键注销。
  不恢复密码登录。
- **实时**：网页后台和小程序员工端一样要实时：连接/重连/收到事件后重新读取资源，不在前端推演状态，断线时显示连接状态并可手动刷新。
  浏览器原生 WebSocket 设不了 `Authorization` 头，后端改为**同时**接受 WebSocket 子协议传令牌
  （`new WebSocket(url, ['pindou.v1', 'bearer.' + 令牌])`，服务端只回显 `pindou.v1`）。不用网址参数传令牌：
  网址会进代理的访问日志，项目规则不许日志里出现令牌。心跳由服务端主动发（WebSocket 控制帧 Ping，浏览器自动回 Pong、页面收不到），推送前复查员工身份的规则不变。
- **三端实时同步（小程序—网页—后端）**：后端只有一个事件中心，任何一端的写请求在库里提交成功后才推「某资源已更新」；
  小程序员工端和网页后台订阅同一条事件流，各自重新读取。网页改了库存，店员手机上马上刷新；小程序里收了款，
  电脑上的订单页立刻变。事件经 PostgreSQL 的 LISTEN/NOTIFY 送到每个副本（见开发约定），不需要 Redis 之类的跨进程广播。
  **顾客端也接上**（已定）：顾客只收到和自己有关的事件（自己的入座申请、计时会话、预约、订单、会员资产），
  后端按账户过滤，不能让顾客从事件里看出别人的动静。员工确认开台、续时、换座后，顾客的「本次手作」立刻更新。
  验收标准：两端各开一个，任一端写，另一端 3 秒内看到。
- **测试**：网页用真浏览器跑端到端（Playwright，`make admin-e2e`），AGENTS.md 已改为浏览器测试只用于网页后台。

## 2. 分批

每批都是「网页先上线、验收通过，再从小程序里删」，任何时候员工都不会两边都找不到。

### 第 0 批 · 确认（已完成）
划分、域名、实时范围已由业主确认（第 5 节）；AGENTS.md 与 product.md 的范围规则已改为允许员工网页后台。

### 第 1 批 · 地基（2026-10-04 已上线 0.0.2，待真机扫码验收）
后端：扫码登录挑战与网页会话（新迁移 + 隔离数据库集成测试）、事件流接受子协议传令牌（测试覆盖令牌失效、员工身份被撤后断开）、静态托管与 CSP。
网页：登录页、侧栏布局、退出、实时连接（状态指示、自动重连、手动刷新）。小程序：员工「扫码登录电脑」入口。部署：后台域名、Traefik 路由与证书。

后端 0.0.2、`pindou-admin.personal.example.invalid`（DNS、证书）与小程序 0.0.2 体验版已上线；还差真机扫码登录电脑的验收。

### 第 1b 批 · 顾客端实时（代码完成，待上线）
后端：事件带上所属账户，顾客连接只收自己的（测试覆盖收不到别人的事件）。小程序顾客端：本次手作、我的预约、订单、会员中心收到事件即重读，后台/重新显示时补读。

实现：受影响账户不在各接口里登记，而是在写入提交后比较前后快照里归属账户的记录（订单、预约、会员流水与资料、入座申请、计时会话、账户资料与任命），新接口自动覆盖；身份变化（顾客被任命、员工被撤）时服务端断开连接让客户端按新身份重连。小程序的连接函数挪到 `services/events.ts` 员工顾客共用，`useCustomerResource(load, { live: true })` 只在上述五页打开。

### 第 2 批 · 最省事、收益最直接的
运营与系统（导出直接下载、全部数据导出、审计）、员工权限、桌码（批量生成、直接打印）。

### 第 3 批 · 库存与订单
商品资料、采购入库、盘点、库存流水；订单历史与退款（逐件回补）；预约设置。

订单与退款网页版代码完成待上线：`/orders` 列表（搜索、状态、分页在网址里）与 `/orders/$orderId` 详情和退款。
订单接口新增 `refundedCents`、`refundableCents`，已退和可退上限由后端算，网页不自行加减。
人工折扣只对待结账订单、是结账前的一步，留在小程序（第 5 批删订单页时并入结账页）。
会员结账订单的退款也在网页订单详情办理（按原付款比例，可分多次，确认前看后端预览）：订单接口新增 `settlement`（member/standard）与 `memberCheckout`（本单结账动过的本金、赠送、积分与线下补付，及累计已退回），列表与详情标出会员结账；小程序「会员结账」里的退款入口待删。

### 第 4 批 · 经营规则与会员资产
规则草稿→预览→发布→停用，充值退款与纠错。

### 第 5 批 · 小程序员工端瘦身（代码完成，待网页上线验收后再上传小程序）
删掉已搬走的页面和入口，工作台精简；员工端宽屏分栏如果不再需要就一并拿掉；更新文档与 skill。

已删：库存、运营与系统、员工权限、桌码四页；订单页只留待结账列表；会员与计时去掉经营规则、会员结账退款、资产纠错与退回充值；预约去掉设置；人工折扣并入结账页。员工分包 147 KB → 88 KB。按「网页先上线、验收通过，再从小程序里删」，小程序这一版要等网页上线并验收后再上传。

## 3. 风险

- **登录是新的攻击面**：后台域名公开可访问。挑战码必须一次性、短时、只能由已登录员工批准，
  批准页要显示登录设备与时间，网页会话可注销，全程审计；不做「记住我」。
- **两端规则漂移**：业务规则全在后端，网页和小程序都只展示；照现在的规矩，前端不算金额、不推演状态。
- **搬迁中途的双份入口**：第 2～4 批期间同一功能两边都有，以网页为准，小程序那份在下一批删除。
- **镜像变大**：嵌入前端后镜像多几 MB，可以接受；前端构建要进 `release.yml`。

## 4. 不做的

- 顾客网页端、H5、独立的网页管理员账号体系、密码登录。
- 经营大屏（把已有的经营数字换个地方再列一遍）仍不做。现场处理用的「现场」看板（平面图、计时提醒、扫码入座确认、到店开台）
  2026-10-05 业主定做、已完成，见 [现场看板计划](plan-live-board.md)。
- 为两端抽共享包或从 api.yaml 生成客户端。

## 5. 业主已定（2026-10-04）

1. 顾客端仍只有小程序；员工常用的留小程序，复杂的去网页后台。
2. 退款只在网页；采购入库（含店员）也去网页。2026-10-06 业主改定：手机也能收货入库并扫码；商品资料、盘点、流水仍在网页。
3. 网页后台域名 `pindou-admin.personal.example.invalid`（2026-10-19 起是 `admin.example.invalid`）。
4. 实时：小程序（员工与顾客）—网页—后端三端同步；顾客端也接入，只收自己的事件。
5. 前端：React 19 + Vite + TypeScript + pnpm；组件库 Semi Design（`@douyinfe/semi-ui`），表格用 Semi Table；
   TanStack 用 Query、Router、Form、Pacer、Devtools，不用 Start、DB、Table、Store、Virtual。
6. 网页后台对所有员工角色开放，能做什么由后端按角色判断。
