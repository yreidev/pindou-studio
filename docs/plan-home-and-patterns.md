# 计划：新首页与老板上传的图纸

> 2026-10-20 制定。背景：老板觉得首页「作品灵感」那 12 张 AI 生成图不像拼豆，像轻奢店的装饰画，想自己找好看的图纸、定期更新；
> 顺带把首页重做成按机型一屏装得下。设计稿是画布「示例工坊小程序首页方案」最下面一排「F 一屏版」（私有画布，2026-10-20 业主认可）。
>
> **进度**：2026-10-20 业主定方案，同日后端（迁移 025）、网页后台、小程序与顾客网页都写完并通过自动测试（后端测试、网页后台与顾客网页的浏览器用例、小程序单元测试与构建）；
> 后端、网页后台和顾客网页 2026-10-20 随 0.0.27 上线，小程序 0.0.27 同日传了体验版；还没在真机上看过。待做：老板发布套餐、传图纸、填地址经纬度和公告 → 小程序体验版真机验收（第 6 节）→ 提审。2026-10-28 核对生产：套餐、888 充值方案、地址经纬度和公告都有了，图纸还一张没上架；没有上架的图纸时小程序叫「做图纸」（第 2 节），提审不用等图纸。

## 0. 已定

| 事项 | 决定 |
|---|---|
| 范围 | 一次做完、一起发版，含「今天还能约」 |
| 图纸信息 | 员工上传图片、填名字、选分类；不填颗数和色数，顾客端也不显示 |
| 分类 | 员工在网页后台自己管：加、改名、调顺序、停用；迁移预置「新手、小动物、水果、花草」 |
| 上新 | 第一次上架起 7 天内自动算「上新」，满 7 天自动去掉；下架再上架不重算 |
| 谁能管 | 图纸、分类、公告：所有员工（店员、店长、老板），都记审计。门店地址和经纬度跟电话、微信一起在「系统设置 → 营业与预约」，只有老板 |
| 游客 | 首页内容游客都能看（公告、今天还能约、本周上新、门店信息），点时段、预约、我的预约、示例工坊社时再登录 |
| 今天还能约 | 最近 4 个整点；每格「余 N 座」= 从这个整点起坐得下最短的已发布套餐、顾客能自助约的位置数（平面图上的一个可约单位算一座，双人桌也算一座）；约满写「已满」置灰；18 点起标「示例工坊夜校」 |
| 点时段 | 进预约页并带上这个时间（`?at=` Unix 秒）：平面图只亮这个时间有空的座位，点座位后日期、时间和套餐（排得进这个时间的最短一个）都已选好 |
| 地址导航 | 老板填地址和经纬度（腾讯地图坐标拾取，GCJ-02）；小程序点「导航」用微信内置地图；不改隐私指引 |
| 营业状态 | 「营业中 / 已打烊 / 今天店休」用「营业与预约」的每天开始、结束时间和歇业日（含每周休息日），不另设营业时间 |
| 公告 | 一段文字（200 字以内），可设到期日（门店日期，过了当天不再显示）；首页只显示一行，点开看全文；没有公告就不显示这一行 |
| 图片 | 存 PostgreSQL（和头像一样）。网页后台选 JPG/PNG（不超过 5 MB），浏览器先缩到长边 1600 像素、压到 1.3 MB 以内再传（接口上限 1.4 MB：base64 之后要放得进 2 MB 的请求体）；服务器重新编码（去掉拍摄地点等元数据），另生成长边 480 的缩略图 |
| AI 图 | 删掉。「作品灵感」页由「图纸」页替代 |
| 发布 | 先发后端和网页后台，老板先传一批图纸、填地址和公告；再传小程序体验版，验收后提审 |

## 1. 首页

从上到下：

1. **员工账号**最上面一条「X 工作台」（同现在）。
2. **状态区**三选一（登录后按接口判断，游客只有「平时」）：
   - 正在店里：状态卡（桌号、已拼多少分钟、入座时刻与计时方式；「呼叫店员」「本次手作」）。
   - 今天有预约（还没到店、今天开始的最近一条）：预约卡（时段、人数与座位、还有多久；「到店扫码入座」「查看预约」）。
   - 平时：「本次手作」大按钮（扫桌码入座）。
3. **三个按钮**：预约座位、我的预约（系统内收费开着时为「消费订单」）、示例工坊社。
4. **公告**一行。
5. **今天还能约**：只在「平时」显示；门店关了自助预约时不显示；今天店休写「今天店休，看看别的日子」，今天没有可约的整点写「今天没有能约的整点了，看看别的日子」，都带「去预约」。
6. **本周上新**：3 张，上新的在前，不够 3 张按图纸顺序补；一张图纸都没有时整块不显示。
7. **门店**一行：营业状态与营业时间、地址；导航、电话、微信（电话拨号、微信号复制；没填的不显示按钮）。

去掉：「近期订单」（收费开着时也不放首页，去「订单」页看）、底部的示例工坊社横幅、旧的作品灵感。

**一屏规则**：小程序样式用固定像素（`PX`，不随屏宽缩放），所以按像素算。每块高度固定，写在 `services/storefront.ts` 的
`homeBlockHeights`，和 `pages/index/index.scss` 里的高度一一对应（`tests/storefront.test.ts` 核对两边一致）：工作台 52、本次手作 76、
状态卡 148、三个按钮 68、公告 44、今天还能约 86、门店 56、问候 36；本周上新一行 80、三张小图 140、三张大图 190；块间距 14，上下各留 12。
可用高度 = 窗口高度 − 状态栏 − 导航栏，减去这一刻要显示的块，本周上新依次试「3 张大图」→「3 张小图」→「一行」，
用大图（或还没有图纸）还有空、登录了就在顶上加问候行；一行都放不下就不放上新。多出来的空平均分进块间距。连固定的块都放不下（横屏、很小的窗口）就照常滚动，不截断。
画布上 iPhone SE 平时是一行（正在店里、有预约时是 3 张小图），iPhone 13/14/15 与 Pro Max 是 3 张大图，360×800 的安卓再加问候行；员工账号多一条工作台，在 SE 上不放上新。

## 2. 图纸页与详情（顾客）

- 底部导航四项：首页、图纸、我的预约（收费开着时为「订单」）、我的。「图纸」是 tabBar 页，按微信要求放主包。
- **店里一张上架的图纸都没有时（2026-10-28 业主定）**：小程序底部第二格和这一页叫「做图纸」，只放「用照片做图纸」「我的图纸」两个入口，
  不显示「今天来示例工坊拼什么？」和「图纸还在准备中」；首页那一栏本来就不显示。业主在网页后台上架第一张图纸，顾客下次打开就叫「图纸」、
  出现店里的图纸，不用发版；全部下架后又变回「做图纸」。起因：0.0.37 提审被驳回「【图纸】页面无具体运营内容」，图纸还没准备好。
  - 业主问过能不能在后台加一个总开关，选了「有上架的图纸才显示」：不用改后端，每张图纸的「上架/下架」就是开关，图纸可以先传、关着「立即上架」存着。
    [微信官方公告](https://developers.weixin.qq.com/community/develop/doc/000044d4a7c7c0031219da0bc56401)要求提审版本与上线运营版本一致，
    点名的是提审时用技术手段藏起违规内容；「有内容才显示」是同一份代码按内容显示，不做专门给审核看的开关。
  - 小程序自带的底栏只能改字和图标，不能单独藏一格，所以是改名而不是藏起来。`app.config.ts` 默认写「做图纸」，
    首页（看「今天来示例工坊拼什么？」那几张）和图纸页（看图纸库）读到有图纸后用 `setTabBarItem` 改成「图纸」（`hooks/patterns-tab.ts`），两边是后端同一个筛选。
  - 还没读到图纸库时按没有算（标题先叫「做图纸」，不放骨架）；读不到只给重试。转发卡片按做图纸说「在示例工坊把照片做成拼豆图纸」，不带分类。
  - 详情页那张下架了、店里也一张都没有时说「店里的图纸暂时都下架了，可以先用照片自己做一张」，按钮「去做图纸」。
- 图纸页：顶上分类筛选（全部、上新、各个启用的分类），两列卡片（图、名字、上新标签）。游客可看。
- 详情页（顾客分包，`pages/customer/pattern/index?id=`）：大图（点开可放大，长按保存由微信提供）、名字、分类、上新标签、「预约来拼这张」。
  后端不单给一张：和图纸页读同一份图纸库，找不到就是下架或删了，说明并给「看全部图纸」。
- 旧的作品灵感页、`services/gallery.ts` 和 12 张 AI 图删除。

## 3. 网页后台

- 新页「首页内容」（所有员工）：
  - 公告：文字、到期日，保存或清空。
  - 图纸：列表（缩略图、名字、分类、上架状态、上新剩几天），上传（选图后预览、填名字、选分类、上架或先存着），改名字和分类、
    换图、上架下架、上移下移、删除（确认一次）。
  - 分类：加、改名、上移下移、停用（停用的分类不在顾客端出现，里面的图纸仍在「全部」里）。
- 「系统设置 → 营业与预约」：门店电话、微信旁加门店地址、纬度、经度，附「腾讯地图坐标拾取」链接；经纬度要么都填要么都不填。

## 4. 接口（`docs/api.yaml`）

| 接口 | 谁 | 说明 |
|---|---|---|
| `GET /storefront` | 游客 | 首页一次读齐：公告（没过期的）、门店联系方式与地址、今天的营业状态、今天还能约（最多 4 个整点）、本周上新 3 张 |
| `GET /patterns` | 游客 | 上架的图纸与启用的分类，按顺序；`scope=all` 给员工，含下架的和停用的分类 |
| `GET /pattern-images/{id}/{size}` | 游客 | 图片本身，`size` 为 `full` 或 `thumb`；地址带版本号，版本对得上时长期缓存 |
| `POST /patterns`、`PATCH /patterns/{id}`、`DELETE /patterns/{id}`、`PATCH /pattern-order` | 员工 | 上传（要 `Idempotency-Key`）、改、删、排顺序 |
| `POST /pattern-categories`、`PATCH /pattern-categories/{id}`、`PATCH /pattern-category-order` | 员工 | 加、改名或停用、排顺序 |
| `GET /storefront/announcement`、`PATCH /storefront/announcement` | 员工 | 读（含已过期的）、保存公告，空文字表示清除 |

- 「今天还能约」在后端算，口径和顾客自助下单一致：在可约范围内（开始结束时间、最短提前、歇业日），没被未过期的预约占着，
  也没被现场定时会话、等结账的会话挡着。
- 写操作推送 `patterns`、`storefront`，网页后台据此刷新；顾客首页不订阅，进页面、回到首页时重读，开着时每分钟重读一次（余座会变）。
- 地址和经纬度放在预约设置里（`reservation_settings` 的 JSON，加字段不用迁移）。

## 5. 数据（迁移 025）

只新增表：`pattern_categories`（名字、顺序、是否启用）、`patterns`（名字、分类、是否上架、第一次上架时刻、顺序、图片和缩略图、
宽高、图片版本、谁在什么时候建和改）、`storefront_announcement`（单行：文字、到期日、最后改的人和时刻）。迁移预置四个分类。
滚动发布时旧版本不碰这些表，退回旧版本前不用处理。

## 6. 验收

- 网页后台：上传、改、排序、上下架、删除、分类、公告、地址都在柜台电脑走一遍；两台电脑同时开着，一台改了另一台跟着刷新。
- 小程序真机：iPhone SE（或同比例的小屏）、普通 iPhone、大屏安卓各看一次首页三种状态都不用滑；游客、顾客、员工各看一次；
  点时段进预约页时间已选好；导航、电话、微信；图纸页筛选、详情放大。
