## 1. 顾客端

1. **预约座位**：先选日子、坐多久（已发布的套餐）、几点开始（每格写还剩几个位，约满的置灰，18 点起标「示例工坊夜校」）；平面图只框出这段时间空着的座位，约满的盖灰。点座位从底部弹出确认：日期、时间、最晚几点到（开始时间加宽限）、团购券码（选填）、备注（选填）、「提交预约」。**点「提交预约」后照旧弹一次「预约须知」，按「确认预约」才提交**（业主 10-20 定，`docs/product.md` 的这条规则不变）。从首页时段点进来（`?at=`）的直接选好那个时间。
2. **本次手作**：扫桌码后直接显示扫到的桌，单人位不再选座号（多座的桌照旧选座），只选坐多久、填团购，「申请入座」→ 等店员确认（三步进度，可以取消申请）→ 计时中（深色页，圆环倒计时，入座时刻、已拼多久、团购，大按钮「呼叫店员」）。
3. **我的预约**：最近一条做成大卡（还有多久开始、几点前到、「到店扫码入座」「取消预约」）；等确认的是小卡；以前的只列最近 3 条，其余点「全部」；最下面是爽约提示。
4. **示例工坊社**：会员码和等级合成一张会员卡，卡上一行储值本金、赠送余额、积分；下面「会员权益 / 生日福利 / 明细」三栏切换；没填生日给一张提醒卡。余额和积分不受系统内收费开关影响，照常显示（`docs/plan-timing-without-billing.md` 第 5 节：会员资产照常显示，收费关着时员工靠手动加减扣储值）。
5. **我的**：深色头部（头像、昵称、等级，点进编辑资料）；两格「示例工坊社」「我的预约」（写下一场的时间）；员工多一行工作台；手机号、联系门店（电话、微信、导航，用首页那份门店信息）、隐私协议；退出登录放最下。去掉和首页重复的「本次手作」「预约座位」。
6. **编辑资料**：大头像、昵称旁边「快速填写」、手机号卡片（快捷填写 / 手动填写）。（画稿上写的是「用微信昵称」「用微信手机号」，2026-10-28 提审要求不写「微信」后改的，第 7 条同。）
7. **登录**：深色品牌页，拼豆心形和「一粒一份喜欢」；主按钮「一键登录」（画稿上是「微信一键登录」带微信图标，2026-10-28 提审被驳回「登录页存在混淆腾讯官方的元素」后去掉了「微信」和图标），次按钮创建账号，下面「我已阅读并同意《隐私协议》」默认不勾、勾了才能登录（2026-10-24 提审被驳回后加的）。从别处点进来的，登录后回到原来要做的事（比如带着 14:00 回预约页），页面上提示「登录后接着……」。
8. **创建账号**：头像（选填）和昵称在一张卡里；先勾隐私协议，再拿微信手机号；手动填写降为文字链，手填的号码显示「未验证」。

## 2. 员工端

1. **底部四格导航**：现场 / 桌位 / 预约 / 会员（员工分包里自己做的导航，不是微信 tabBar），现场和预约上标待办数。
2. **现场**（原工作台）：老板、店长、店员看到的一样，不再按角色换顺序；标题统一叫「现场」，名字旁标角色（业主 10-20 定）。从上到下：空闲 / 使用中 / 需关注三个数；顾客呼叫（我去处理 / 已处理 / 知道了，振动规则不变）；「等你处理」——扫码入座申请直接在这里「确认开始计时 / 改团购 / 拒绝」，超时、快到点、待确认预约各一行；大按钮「客人到店，计时开台」去桌位；收货入库、连电脑两格；品牌精神与版本号。
3. **桌位**：平面图上每张桌按状态着色（空闲绿框、使用中深色并写剩几分钟、快到点金色、超时红色、停用斜纹），图下列出超时和快到点的桌；筛选「全部 / 空闲 / 使用中 / 需关注」保留。停用、启用仍只给店长和老板。
4. **开台**改成桌位页的底部弹层，不再跳「开台」页：谁来坐（散客 / 扫会员码 / 搜昵称或手机尾号）、坐多久（已发布套餐的时长、到打烊、自由计时，加「其他时长」：滚轮按 30 分钟一档，30 分钟到 8 小时，业主 10-20 定）、默认从现在开始计（可以改早，回填规则不变）、「确认开台」。
5. **会话**也改成弹层，不再跳「会话」页；扫码入座的按座会话也用这一个弹层，不再跳「会员与计时」的列表：剩余或超时的大数字，开始 / 时长 / 到点 / 团购，续时、暂停、换桌，主按钮「结束，放出座位」，「撤销这次开台」放最下。到打烊的照旧不给暂停、续时。
6. **「会员与计时」拆开**：计时并进现场和桌位，剩下的做成「会员」页：最上面「扫会员码」和搜索；会员卡（是谁、等级、手机尾号、生日，储值本金、赠送余额、积分）；「到店充值 / 积分兑换 / 手动加减」三格，各自从底部弹出办理（规则不变，不受收费开关影响）；生日礼物待领直接核销；新增「这位顾客今天」，列出今天的预约，已确认的可以直接开台。
7. **预约到店**：分今天 / 明天 / 以后，按开始时间排成时间线；过了时间没来的置顶成红卡（标记爽约 / 顾客说不来了）；每条只留一个主按钮（确认预约，或到店开台），取消、爽约收进「⋯」；「代客登记」做成右下角的按钮，单独一页。
8. **预约到店没账号也能开台**（业主 10-20 定）：代客登记时只写了称呼、没关联账号的预约，到店时店员可以直接当散客开台，按预约的套餐时长计时；顾客愿意注册的仍可以顺手关联。要改后端：现在 `internal/app/reservations.go` 的 `reservationSeat` 没账号就报「散客预约到店后请先选择顾客账户」。
9. **代客登记**：顾客（搜账号，或只写称呼）、坐多久、哪天几点、座位按区域列出那个时段空着的（不再先选桌、再选座号）、团购券码和备注选填。
10. **收货入库**：扫码区放大，数量用加减按钮，第一次进货没填进价的那行标红，底部写合计和还差什么。规则不变。
11. **连电脑**：「扫码登录电脑」「扫码给电脑」合成一页：扫登录码、手机当扫码枪（显示上一次发给电脑的结果）、全部退出。

## 3. 系统内收费打开时

收费现在关着，下面这些功能代码里都在，新页面里留好位置；画布最下面一排「系统内收费打开时」8 张，2026-10-20 业主认可：

- 顾客端：预约确认写「到店付 ¥」；本次手作的时长卡带价格，底栏写「现在不付钱，用完结账」；底部第三格是「订单」（还没结清的做成深色大卡，以前的列表，右上角进我的预约）；订单详情（已付、还差，消费明细含超时加收，优惠记录，付款记录，退款时多一栏退款记录，订单编号可复制）。
- 员工端：现场「等你处理」多一行「N 单待结账」；会话弹层多应收和后端写的计费说明，续时按钮写加价，底部「停止计时」「去收款」两个按钮；「待结账」页分「可以收了」（已停止计时、部分付款）和「还在计时」两段，按桌号列；结账页一页从上到下：这次线下要收多少（原应收、会员优惠、储值抵扣）、顾客（换顾客）、明细（数量加减、扫码或搜索加商品服务）、会员抵扣（储值、积分）、店长老板才有的人工折扣与免单、线下收款（微信 / 支付宝 / 现金，这一笔收多少，可分笔），底部「确认收款」。
- 会员资产（示例工坊社的余额积分、员工会员页的充值、兑换、手动加减）不受开关影响，画在顾客端和员工端那两排，不在这一排。
